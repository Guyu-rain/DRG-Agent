## 3. 团队分工建议（4-5 人）

### 角色分配

| 角色 | 职责 |
|------|------|
| **项目经理** | 进度跟踪、会议组织、需求文档（已完成）、概要设计协调、项目管理文档 |
| **架构师/后端开发** | 系统架构设计、DRG 规则引擎（核心）、智能体编排（LangGraph）、API 开发 |
| **前端开发** | React 前端全部页面、组件开发、UI/UX 设计、前端状态管理 |
| **后端开发/AI 开发** | LLM 客户端封装、Prompt 设计、文档/测试智能体、Celery 任务 |
| **测试人员** | 测试策略制定、测试用例编写与执行、测试报告、缺陷跟踪 |

### 人力占比估算

| 模块 | 工时占比 | 说明 |
|------|----------|------|
| DRG 规则引擎 | 20% | 核心算法，确定性逻辑，独立性强 |
| 智能体编排 | 15% | LangGraph 工作流设计与 Prompt 工程 |
| 后端 API | 15% | FastAPI 路由、服务层、ORM |
| 前端开发 | 25% | 页面多、交互复杂，工时最大 |
| 测试 | 15% | 测试用例、集成测试、测试报告 |
| 文档与项目管理 | 10% | 各类交付文档 |

## 4. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| DRG 规则文件格式不明确 | 中 | 高 | 先用课程示例构造最小规则集，规则接口保持与文件格式解耦 |
| 大模型 API 不稳定或限流 | 高 | 中 | LLM 仅用于非关键路径（解释、文档生成）；核心入组不依赖 LLM |
| 前端开发人力不足 | 中 | 中 | 使用 Ant Design 加速开发；优先完成核心页面（入组工作台、文档系统） |
| 课程计划时间紧 | 高 | 高 | 严格按 MoSCoW 优先级实现；阶段 4-5 可压缩非核心功能 |
| 团队协作沟通不足 | 中 | 中 | 每周至少一次站会；接口先定义后实现；前后端解耦 |
